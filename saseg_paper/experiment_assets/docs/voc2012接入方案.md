# VOC2012 接入与处理方案

## 1. 文档目的

本文档用于说明如何将已经下载并解压好的 `PASCAL VOC 2012` 语义分割数据接入当前 `SASeg` 项目，并对齐项目现有的 `A1 / A2` 双协议。

目标不是立刻改完所有代码，而是先把下面几件事讲清楚：

- 当前 VOC 原始数据中哪些文件真正需要使用
- 在本项目中应如何组织和预处理 VOC 数据
- 如何把 VOC 映射为 `known / seen unknown / unseen unknown`
- 现有代码与 VOC 之间有哪些关键不一致点
- 后续实现时最少需要改哪些模块

## 3. VOC2012 中真正要用哪些文件

对于当前项目的语义分割任务，推荐只使用：

### 3.1 图像

- `VOC2012/JPEGImages/<image_id>.jpg`

例如：

- `VOC2012/JPEGImages/2007_000032.jpg`

### 3.2 语义分割 GT

- `VOC2012/SegmentationClass/<image_id>.png`

这是按像素存储类别索引的语义分割标注。

### 3.3 图像划分文件

- `VOC2012/ImageSets/Segmentation/train.txt`
- `VOC2012/ImageSets/Segmentation/val.txt`
- `VOC2012/ImageSets/Segmentation/trainval.txt`

当前确认数量为：

- `train.txt`：1464
- `val.txt`：1449
- `trainval.txt`：2913

### 3.4 当前阶段不需要的文件

- `Annotations/*.xml`
  - 这是 detection / bbox / instance 相关信息，当前主线不需要
- `SegmentationObject/*.png`
  - 这是 instance-level object segmentation，不是当前语义分割主入口

## 4. VOC2012 的标签语义

VOC 语义分割常用标签编码如下：

- `0`：background
- `1-20`：20 个前景语义类
- `255`：ignore / void

这一点非常关键，因为当前项目的 CT 数据没有显式 `ignore` 像素，而 VOC 有。

因此，接入 VOC 时必须明确：

- `255` 不能当作 background
- `255` 也不能当作 unknown
- `255` 必须在训练损失、边界图构造和评估中被排除

如果忽略这一点，训练和评估都会被污染。

## 6. 在 SASeg 里如何定义 A1 / A2

### 6.1 A1（Seen Unknown Structured Abstention）

训练和验证都把：

- `sheep, sofa, train`

作为 unknown 联合区域。

也就是说：

- train unknown labels = seen unknown
- val unknown labels = seen unknown

核心验证点：

- `M=2` 能否形成 coherent unknown mask
- `M=0` 后 unknown F1 是否显著崩塌

### 6.2 A2（Unseen Unknown Detection Generalization）

训练时把：

- `sheep, sofa, train`

作为 unknown 监督；

验证时把：

- `motorbike, tvmonitor`

作为 unseen unknown。

也就是说：

- train unknown labels = seen unknown
- val unknown labels = unseen unknown

核心验证点：

- 排序指标能否保持较高
- 最终 unknown mask F1 是否仍明显落后

## 7. 推荐的数据使用策略

### 7.1 第一阶段：只用官方 `train / val`

第一轮接入建议采用最简单方案：

- 训练集：`ImageSets/Segmentation/train.txt`
- 验证集：`ImageSets/Segmentation/val.txt`

理由：

- VOC 官方 `val` 有 GT，可直接做定量评估
- 当前论文扩展实验只需要稳定复现现象，不需要引入额外自定义拆分
- 最容易与论文写法对齐

### 7.2 关于 `test`

当前项目的数据工厂默认会构建 `train / val / test` 三个 split，但 VOC 官方 `test` 在本地 trainval 包中并不提供完整可评估标注。

因此第一版最稳妥的处理方式是：

- `train` = 官方 `train`
- `val` = 官方 `val`
- `test` = 暂时复用官方 `val`

这只是为了兼容当前工程接口，不代表论文里需要报告两套结果。

论文写作上仍然只需要写：

- train on VOC train
- report on VOC val

## 8. 推荐的预处理输出格式

当前项目的预处理输出格式定义在：

- [preprocess.py](/my_storage/chen/saseg/code/data/preprocess.py)

现有输出目录是：

- `dataset/preprocessed/synapse/...`
- `dataset/preprocessed/amos22/...`
- `dataset/preprocessed/mood/...`

VOC 建议新增为：

```text
dataset/preprocessed/
  voc2012/
    train/
      <image_id>_img.npy
      <image_id>_lbl.npy
      <image_id>_bnd.npy
    val/
      <image_id>_img.npy
      <image_id>_lbl.npy
      <image_id>_bnd.npy
    test/
      <image_id>_img.npy
      <image_id>_lbl.npy
      <image_id>_bnd.npy
```

推荐约定：

- `_img.npy`
  - `float32`
  - 形状建议为 `(3, H, W)`，保存 RGB 三通道
- `_lbl.npy`
  - `uint8`
  - 形状 `(H, W)`
  - 保存原始 VOC 类别索引图，保留 `255`
- `_bnd.npy`
  - `float32`
  - 形状 `(H, W)`
  - 由 label 图生成 soft boundary

### 8.1 为什么建议保存原始标签图，而不是预先折叠成 known/unknown

因为当前项目已经在数据集类里通过 `known_labels` 和 `unknown_labels` 做动态 union：

- [dataset.py](/my_storage/chen/saseg/code/data/dataset.py#L75)

如果 `_lbl.npy` 中保存原始 VOC 类别索引，那么：

- A1 和 A2 可以共用同一套预处理结果
- 只需通过配置切换 `seen_unknown_labels / unseen_unknown_labels`
- 后续想改 split，不需要重新预处理全部数据

这是最灵活、也最符合当前工程结构的做法。

## 9. VOC 接入时与当前项目的关键不一致

这是最需要提前说明的部分。

### 9.1 当前项目默认是单通道 CT，VOC 是 RGB

当前数据样本定义和模型注释都默认输入是单通道：

- [dataset.py](/my_storage/chen/saseg/code/data/dataset.py#L4)
- [encoder.py](/my_storage/chen/saseg/code/models/encoder.py#L9)

其中编码器当前做法是：

- 输入 `(B, 1, H, W)`
- 再 `repeat` 成 `(B, 3, H, W)` 喂给 Swin

这对 CT 合理，但对 VOC 不合理。

因此 VOC 接入必须二选一：

1. **推荐方案**
   - 让 VOC 数据集直接返回 `(3, H, W)` 图像
   - 修改 encoder，使其支持：
     - 单通道输入：repeat 到 3 通道
     - 三通道输入：直接送入 backbone

2. **不推荐方案**
   - 把 RGB 先转灰度

第二种会损失太多自然图像信息，不建议。

### 9.2 当前增强默认是给单通道 CT 设计的

当前增强配置在：

- [default.yaml](/my_storage/chen/saseg/code/configs/default.yaml)

当前增强包括：

- `brightness_limit`
- `contrast_limit`
- `rotate`
- `scale`
- `hflip`

其中亮度/对比度增强逻辑需要确认是否直接支持 3 通道图像；如果当前实现只假设 `(1, H, W)`，则需要同步扩展。

### 9.3 当前 boundary map 逻辑需要 ignore-aware

当前边界图生成逻辑在：

- [preprocess.py](/my_storage/chen/saseg/code/data/preprocess.py#L80)

它目前默认任意标签差异都记为边界。

对 VOC 来说要避免：

- `255` 与有效类之间的边界被错误强化

因此 VOC 版本建议：

- 在构造 boundary map 时，把 `255` 区域先排除
- 或者生成边界后再把 `255` 区域清零

### 9.4 当前 `_label_to_masks()` 没有 ignore 机制

当前 label 到 known/unknown 的转换逻辑在：

- [dataset.py](/my_storage/chen/saseg/code/data/dataset.py#L75)

它默认所有未被选中的像素都会自然落入背景/其他区域。

对 VOC 来说这是不够的，因为 `255` 不能被当背景。

推荐做法：

- 在 dataset sample 中额外提供 `ignore_mask`
- 或者统一把 `255` 像素在 loss 与 metric 中屏蔽

如果只改 dataset 不改 loss/eval，仍然会出错。

## 10. 建议的实现步骤

### Step 1：新增 VOC 预处理入口

在：

- [preprocess.py](/my_storage/chen/saseg/code/data/preprocess.py)

新增 `process_voc2012()`，完成：

- 读取 `train.txt / val.txt`
- 读取 `JPEGImages/*.jpg`
- 读取 `SegmentationClass/*.png`
- resize 到项目统一分辨率
- 保存 `_img.npy / _lbl.npy / _bnd.npy`

建议初版直接沿用当前 `image_size=512`，即：

- 图像双线性 resize 到 `512 x 512`
- mask 最近邻 resize 到 `512 x 512`

虽然这会带来一定形变，但能最大程度复用当前代码和配置。后续若结果对形变敏感，再考虑 pad/crop 方案。

### Step 2：新增 `VOCDataset`

在：

- [dataset.py](/my_storage/chen/saseg/code/data/dataset.py)

新增 `VOCDataset`，接口尽量与 `SynapseDataset / AMOS22Dataset` 对齐。

建议支持：

- `split in {train, val, test}`
- `known_labels`
- `unknown_labels`
- `ignore_label=255`

### Step 3：在 `build_datasets()` 中接入 `voc2012`

在：

- [dataset.py](/my_storage/chen/saseg/code/data/dataset.py#L368)

扩展 `cfg.data.dataset` 支持：

- `voc2012`

然后按当前 `A1 / A2` 逻辑，像 Synapse 一样处理：

- `A1`：train/val/test 都用 seen unknown
- `A2`：train 用 seen unknown，val/test 用 unseen unknown

### Step 4：修改 encoder 支持 RGB

在：

- [encoder.py](/my_storage/chen/saseg/code/models/encoder.py#L103)

建议改为：

- 如果输入通道数是 `1`，则 repeat 到 `3`
- 如果输入通道数是 `3`，则直接输入 backbone

这是接入 VOC 与后续 Cityscapes 的必要改动。

### Step 5：补充 VOC 配置文件

建议新增：

- `code/configs/voc2012_a1.yaml`
- `code/configs/voc2012_a2.yaml`
- `code/configs/voc2012_m0.yaml`

内容参考：

- [default.yaml](/my_storage/chen/saseg/code/configs/default.yaml)

需要重点改的字段：

- `data.dataset: voc2012`
- `data.num_known_classes: 15`
- `data.known_labels`
- `data.seen_unknown_labels`
- `data.unseen_unknown_labels`
- `train.save_dir`
- `inference.output_dir`

## 11. 第一轮最小验证建议

在全部训练前，先做下面几个小检查：

### 11.1 数据检查

- 随机抽 10 张图，确认：
  - `jpg` 和 `png` 一一对应
  - resize 后图像与标签空间对齐
  - `255` 区域没有被错误吞成背景

### 11.2 split 检查

- 统计 `train` 和 `val` 中每个 VOC 类出现的样本数
- 确认：
  - 15 个 known 在 train 中足够常见
  - 3 个 seen unknown 在 train/val 中都出现
  - 2 个 unseen unknown 在 val 中有足够样本

这一步非常重要，否则 A2 可能因为正样本太少而不稳定。

### 11.3 工程检查

- 单 batch forward 是否正常
- encoder 是否正确接受 RGB
- loss 和 eval 是否正确跳过 ignore 区域

### 11.4 训练检查

先做一个极小规模 sanity run：

- 训练 1-3 epoch
- 确认 loss 正常下降
- 确认 unknown mask 不是全零/全一

## 12. 关于是否要接 SBD / trainaug

当前阶段**不建议**一开始就引入 SBD 或 VOC trainaug。

理由：

- 当前目标是验证 structured abstention 现象是否能在自然图像上复现
- 不是追求 VOC segmentation benchmark 的极限性能
- 先用官方 VOC2012 `train / val` 即可建立可写论文的第一轮结果

如果第一轮结果太不稳定，再考虑是否引入扩充标注。

---

## 13. 当前最推荐的落地策略

最稳妥的执行顺序是：

1. 先完成 `VOC raw -> preprocessed voc2012` 的数据落盘
2. 先让 `VOCDataset` 跑通，并正确处理 `ignore=255`
3. 先修改 encoder 支持 RGB
4. 先做一个 `A1` 小实验验证 `M=0` 是否崩塌
5. 再做 `A2` 实验验证 detection-structuring gap

不要一上来就同时改：

- VOC
- Cityscapes
- 完整 ablation
- 新分析图

先把 VOC 作为第一块自然图像验证打通，再复制到 Cityscapes，会顺很多。

---

## 14. 一句话总结

对于当前项目，VOC2012 的最合理处理方式是：

> 使用 `JPEGImages + SegmentationClass + ImageSets/Segmentation` 作为原始输入，保留原始类别索引图与 `255 ignore`，预处理到 `dataset/preprocessed/voc2012`，在数据集层通过 `known / seen unknown / unseen unknown` 动态映射 A1/A2 协议，并同步把编码器与损失评估逻辑从“单通道 CT”扩展到“支持 RGB + ignore-aware”的通用语义分割输入。

这条路线与当前 `SASeg` 的工程结构最兼容，也最适合作为后续 `Cityscapes` 接入的模板。
